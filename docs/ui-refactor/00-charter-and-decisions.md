# 00 · 项目章程与决策记录

> 阶段 0 交付物 · 2026-10-01 · 状态：已定稿
> 本文档定义本次 UI 彻底重构的范围、决策、约束与验证结论。后续阶段以此为准。

## 1. 背景

SeatFlow 的 Presentation.Avalonia 层经多轮功能迭代后出现典型的技术债症状：
UI 臃肿（全项目 ~22K 行，含生成代码）、页面级重复模式（5 套脏检查、5 份 `CanLeaveAsync`、5 处 `_dialogLock`）、
生命周期管理不一致（Singleton/Transient 混用、静态可变状态、订阅泄漏）、
画布类界面全量重建（座位图/会场预览）、以及引导系统与页面 VM 的深度耦合。
本次决定**彻底重构**而非局部修补。

## 2. 目标与非目标

**目标**
1. 盘点现状并给出可核对的性能/体验问题清单（带代码或运行时证据）。
2. 重新设计信息架构与视觉语言，显著降低复杂度、臃肿感与无意义动效。
3. 明确数据生命周期、控件策略与技术选型，并产出可执行的分阶段重构计划。
4. 交付可在本地 WASM 服务 + MCP 中查看的 HTML 高保真样机。

**非目标（本轮）**
- 不实施代码重构（阶段 6 计划批准后另行启动）。
- 不改动业务规则与策略引擎语义（座位编排算法、文件格式语义）。
- 不降级 Avalonia/.NET 版本。
- 不追求 Web 与桌面功能完全对等（逐项重审，允许浏览器能力替代）。

## 11. 代码库初勘（codebase-design 视角）

- **模块深度**：`IApplicationFacade` 是 UI 与应用层的深接口（良好）；但 Presentation 层内部多数“模块”是浅的——
  页面 VM 直接持有数据加载、脏检查、对话框、导航等横切逻辑，导致同一行为在多个 VM 中重复（详见 01）。
- **接缝位置**：跨页横切能力（脏检查、对话框门、繁忙状态、列表加载、导出流程）应下沉为共享服务/基类，
  接缝放在 Presentation 内的服务层，而非每个 VM 各自实现。
- **测试面**：UI 层目前无测试项目；VM 逻辑（脏检查、状态机、命令）适合成为首批 XUnit v3 测试对象，
  View 渲染与交互留给 Avalonia.Headless（阶段 5 评估）。
- **生命周期边界**：页面的“数据生命周期”与“视图生命周期”未分离——Singleton 页面常驻但数据随导航刷新，
  Transient 页面又丢失状态；需要显式的页面状态机（阶段 3 设计）。
