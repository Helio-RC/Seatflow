# 03 · 全新 UI 设计（UI Redesign）

> 阶段 3 交付物 · 2026-10-01 · 状态：**待审核（强制门 3，含方向选择）**
> 依据：`01-current-ui-inventory.md`（现状盘点）、`02-performance-ux-diagnosis.md`（性能诊断）、`00` 决策 D2/D3/D5。
> 样机：`direction-mocks/`（同一代表页「排座工作台」× 三套令牌），截图 `assets/design-directions/`。

## 1. 设计目标与原则

1. **性能是设计约束，不是事后优化**：任何交互设计必须先声明其主线程成本（见 §7 与 M1–M6）。
2. **一个工作台，而不是九个孤岛**：以「选数据 → 生成 → 查看 → 导出」的主工作流组织导航与页面职责。
3. **信息密度分层**：常驻仅保留当前任务必需的信息；其余进页签/抽屉/详情区。
4. **动效只为状态连续性服务**：默认零装饰动画；导航即时（或 ≤120ms 且不阻塞）。
5. **每像素都要有令牌**：颜色/间距/圆角/字阶全部来自令牌表，禁止魔法值（对齐 `frontend-ui-engineering-avalonia` 规范）。
6. **可访问性基线与双主题**：明/暗主题同等打磨；键盘可达、焦点可见、对比度 ≥4.5:1。

## 2. 新信息架构（IA）提案

### 2.1 导航模型（保留侧栏，分组化）

```
工作流   排座工作台        ← 核心，默认首页（取代 Home 作为入口）
资料     人员名单 / 会场与布局
规则     策略配置
记录     历史快照
──────────────
底部常驻  设置 / 关于
```

- **Home 精简**：现 Home 承担问候+快捷链接+RELEASE 渲染三块。新方案：将「欢迎与更新说明」压缩为**排座工作台空态**中的一个紧凑卡片（首次启动/无数据时出现），Home 页面取消。用户首屏直达任务。
- **「自由点管理」并入「会场与布局」**：自由布局本质是会场的一种布局类型（当前 `VenueConfiguration` 已有 Freeform 分支，且快照/排座共用同一布局模型）。合并为单页三类布局编辑器，**功能全保留**（导入 CSV/JSON、坐标表格、预览、保存）。这消除了一处页面级重复（列表加载/脏检查/导出流程）。
- **排座工作台三栏化**：左「数据选择」→ 中「画布」→ 右「上下文检查器（页签）」。当前右侧纵向堆叠的 策略/未分配/记录/消息 改为 **页签**，避免长滚动与状态互踩（对照 `SeatingArrangementView.axaml:489-814`）。
- **侧栏底部固定区**保持；中部导航改为**可滚动容器**并设最小高度保护——修复 I-01（小高度视口溢出覆盖）。
- **引导（onboarding）随新 IA 重写目标**：启动引导步骤映射到新页面/新控件（`onboarding_config.json` 的 `target` 更新）；步骤语义与覆盖范围不变（功能全保留原则）。

### 2.2 页面职责表（新 IA）

| 页面 | 职责 | 相对现状 |
|---|---|---|
| 排座工作台 | 选择会场/名单 → 生成 → 画布调整 → 快照/导出 | 取代 Home 成为默认入口；右栏页签化 |
| 人员名单 | 数据集管理 + 学生表格编辑 | 结构保留；表格改轻量虚拟化方案（§4） |
| 会场与布局 | Grid/Polar/Freeform 三种布局编辑 + 预览 | 合并原「自由点管理」，统一生命周期 |
| 策略配置 | 策略启停/优先级/参数/配置块 | 结构保留；左栏详情滚动区独立 |
| 历史快照 | 快照浏览/预览/回滚/批量删除 | 生命周期从 Transient 改为与其余页面一致的缓存策略（离开保留、显式刷新） |
| 设置 / 关于 | 设置分组卡片 / 关于 | 保留；设置卡片增加分组锚点导航 |

## 3. 视觉方向（三选一）

> 代表页截图（1440×900）：
> A `assets/design-directions/direction-a.png` · B `.../direction-b.png` · C `.../direction-c.png`
> 在线对比：`direction-mocks/index.html`（本地服务 8091）。

### 3.1 方向 A ·「精炼 Fluent」（浅色，风险最低）

- **定位**：延续 Fluent 语言与用户肌肉记忆，做减法：统一令牌、收紧间距、去装饰阴影与无意义过渡。
- **色板**：`#F6F7F9` 底 / `#FFFFFF` 面 / `#E4E7EC` 边框 / `#2563EB` 强调 / `#1B1F27` 主文字。
- **字体**：Inter + 系统 CJK；字阶 11/12.5/13.5/16；字重 400/500/650。
- **形态**：圆角 4/6/10；仅浮层有阴影；画布浅灰底、白色面板。
- **优点**：迁移与验收成本最低；教师用户无需重新学习。
- **风险**：与现状差异最小，「臃肿感」主要靠 IA/密度解决，视觉记忆点弱。

### 3.2 方向 B ·「方格纸」（浅色，学科气质）

- **定位**：取自教室方格座位表与备课本的视觉母题——**画布即方格纸**，发丝格线贯穿工作区；数据（人数/座位数/优先级）用等宽数字对齐。
- **色板**：`#F2F4F6` 冷纸底 / `#FFFFFF` 面 / `#D9E0E7` 格线 / `#3B5BDB` 靛蓝 / `#16202B` 墨字。
- **字体**：同 A，但数字统一 tabular；标题字重更收敛。
- **形态**：圆角 3/5/8；**零阴影、发丝边框**；画布背景为 24px 方格纸（`repeating-linear-gradient`）。
- **优点**：辨识度最高且与「排座位/画座位表」心智强相关；纸面感天然克制装饰；打印导出与本视觉一致。
- **风险**：格线在低端设备上的绘制成本需验证（静态背景图，成本可控）。

### 3.3 方向 C ·「夜校工作台」（深色，高密度）

- **定位**：为长时间排座/值班场景的深色高密度界面；**黑板质感画布**（深墨绿 + 粉笔格线）+ 琥珀强调。
- **色板**：`#0B1020` 底 / `#121A2E` 面 / `#22304A` 边框 / `#F0B429` 琥珀 / `#E7ECF5` 文字。
- **字体**：同 A；密度更高（行高 30、控件 28、座位 36）。
- **形态**：圆角 3/5/8；无阴影、边框优先；焦点环用琥珀。
- **优点**：焦点最集中，画布对比度好；长时间使用眼睛负担小（夜间/昏暗教室）。
- **风险**：日间办公环境默认深色体验两极化；需同时维护浅色变体（本方向要求明主题同步提供，但个性主要在暗色）。

### 3.4 方向对比（供决策）

| 维度 | A 精炼 Fluent | B 方格纸 | C 夜校工作台 |
|---|---|---|---|
| 与现状的距离 | 小 | 中 | 大 |
| 辨识度/记忆点 | 低 | **高** | 高 |
| 教师用户亲和 | 高 | **最高（学科母题）** | 中（取决于使用时段） |
| 明/暗双主题成本 | 低 | 中（格线×两主题） | 中（浅色变体需定制） |
| 迁移成本/风险 | 低 | 中 | 中高 |
| 性能风险 | 无 | 低（静态格线背景） | 低 |
| 建议 | 稳健选项 | **推荐**（与产品语义最契合） | 备选（可作暗色模式的特化皮肤） |

> 设计提示：三方向共享 §2 的 IA、§4 的组件策略与 §6 的生命周期框架；方向选择只决定令牌与视觉签名，不推翻结构。

## 4. 组件与控件策略（Avalonia 落地）

**原则**：优先内建控件 + 令牌定制；自定义只用于「内建无法表达且高频」的场景。当前项目仅 1 个自定义控件（`PhaseGuideIndicator`），问题不在自定义，而在页面级重复逻辑。

| 场景 | 方案 | 说明 |
|---|---|---|
| 学生名单表格 | `ListBox` + `VirtualizingStackPanel`（**修正 ScrollViewer 包裹**）；行内 TextBox 改为「显示 TextBlock，点击进入编辑」轻量模式 | 每行控件数从 5 → 1–2，虚拟化恢复（官方性能文档 §1） |
| 长列表（快照/未分配） | 内建 `ListBox`（保持虚拟化） | 现状已可用 |
| 座位画布 | **自绘 `Control.Render` 或单层 ItemsControl+Canvas 二选一 → 阶段 5 技术选型裁决**；设计侧要求：编译绑定（禁用 ReflectionBinding）、增量更新、每帧不做集合重建 | 对齐 RC-3；候选方案在 05 文档给出对比与 spike 结论 |

> **布局类型完整性要求（真实实现必修）**：Grid / Polar / Freeform 三种布局的坐标建模、渲染、拖拽与命中测试均须完整支持；
> 阶段 4 样机仅以 Grid 为主并演示简化的 Polar（环+中心）与 Freeform（坐标散点）预览，不得视为可裁剪范围。
| 页签检查器 | `TabControl`（轻定制模板） | 替代右栏纵向堆叠 |
| 命令栏/按钮 | 内建 `Button` + 令牌样式；禁止每个按钮新建模板 | 统一 `ControlTheme` |
| 对话框 | 现有 `DialogService`/`WebDialogService` 保留，令牌化外观 | 功能不动 |
| 空/加载/错误态 | 统一 `StateView` 组合（四态模板：Loading/Error/Empty/Content） | 消除 3+ 页面各自实现 |
| 图标 | 保留 FluentIcons（已用） | 不引入新图标库 |

**避免 AI 审美**（自查清单）：无紫色渐变堆叠、无统一大圆角卡片网格、无重阴影/毛玻璃、无 lorem 数据、无 24px 全员内边距。

## 5. 动效政策（明确允许清单）

| 动效 | 允许 | 时长 | 说明 |
|---|---|---|---|
| 导航/页面切换 | ❌ 默认删除 | — | 现状 200ms 淡出 + 100ms 间隔强制延迟（I-02/RC-2）；如保留仅可 ≤120ms 淡入且不阻塞输入 |
| 侧栏折叠 | ✅ | 150ms | 有明确状态语义 |

## 6. 数据生命周期框架（统一模型）

### 6.1 页面状态机

```
Idle → Loading → Ready ─┬→ Dirty → Saving → Ready
                        ├→ Error → Retry → Loading
                        └→ Empty → (首次操作) → Loading
离开页面：CanLeave(Dirty?) → 确认/保存/放弃 → Cancel in-flight → 释放临时资源（页面缓存策略见下）
```

- **构造器禁止 fire-and-forget**（现 8 处）：加载一律由 `OnEnterAsync()` 显式触发，携带 `CancellationToken`，离开时取消。
- **统一脏检查**：`IEditableDocument`（`IsDirty` / `MarkClean` / `SerializeSnapshot`）或共享 `DirtyTracker`，消除 5 套实现。
- **统一离开拦截**：`CanLeaveAsync` 模板方法下沉到基类/服务，配套统一 `IDialogGate`（消除 5 处 `_dialogLock`）。
- **页面缓存策略**：页面 VM 统一 **Singleton + 显式刷新**（进入时若数据版本未变则不重载）；`SnapshotHistory` 的 Transient 特例取消。
- **订阅治理**：静态可变状态清零（`KeyboardShortcutHandler.ShortcutConfig`、`FileDropHandler._host`、`ViewModelBase.Dialog`）；订阅必须可退订（`IDisposable`/弱引用），位图与 Popup 必须释放。
- **Busy/Loading 统一**：单一 `IBusyScope`，页面级遮罩与命令禁用由它驱动。

### 6.2 画布数据更新约定

- 座位集合的增删改走**增量通知**（ObservableCollection 精确变更或 `IReadOnlyList` 整体替换 + 版本号），禁止「参数变一次、全量重建一次」。
- 会场参数预览：**输入去抖 ≥120ms + 合帧**；连续调整期间只重算一次（对齐 RC-1）。
- 生成/导入等长任务：分帧或后台计算 + `DispatcherPriority.Background` 提交。

## 7. 性能对策映射（设计层承诺 → 指标）

| 诊断根因 | 设计对策 | 验收指标（02 §6） |
|---|---|---|
| RC-1 会场预览 | 去抖 + 增量更新 + 画布渲染选型 | M1 ≤50ms/次 |
| RC-2 页面切换 | 删动画、显式生命周期、加载可取消、页面缓存 | M2 ≤100ms |
| RC-3 座位画布 | 编译绑定、增量更新、自绘/虚拟化选型 | M3/M3b |
| RC-4 启动阻塞 | 首帧必需 vs 后台任务分级；杜绝启动解析全部 VM | M4 ≤3s |
| RC-5 名单/渲染 | 轻量行模板 + 虚拟化恢复；统一令牌减少过度重绘 | M5 |

## 8. 可访问性与 i18n

- 键盘：全部交互控件可达；座位画布支持方向键移动选中座位（新增）；焦点环令牌化且 ≥3:1。
- `AutomationProperties.Name` 覆盖图标按钮（现状缺失面大，重构时补全）；LiveSetting 用于状态栏/策略消息。
- 对比度：正文 ≥4.5:1、大字 ≥3:1；状态色必须配文字/图标（现状已部分满足）。
- i18n：消除硬编码中文（`StudentPickerView.axaml:11`、`SeatPositionPickerView.axaml` 6 处）；新 UI 文案全部走 `.resx`；中英文版式在样机中验证（用户可切换）。

## 10. 审核决策点

1. **视觉方向**：A / B / C 或混合（例如「B 的格纸语言 + C 的暗色皮肤」）。**推荐 B**。
2. **IA 变更**：合并「自由点管理」到「会场与布局」、取消独立 Home（入口=排座工作台）、右栏页签化、侧栏分组。若希望保留 9 页结构，可降级为「仅分组+页签化」。
3. 动效政策（§5）是否照此执行。
4. 数据生命周期框架（§6）是否作为阶段 5/6 的强制约束。

下一阶段（阶段 4）将按选定方向实现 React/Vite 高保真可交互原型（全页面 + 关键交互 + 明暗/中英切换）。
